# Maintenance and release evidence

## Architecture and trust boundaries

Conspire is a C++ oatpp server with a build-time embedded browser client. Clients connect
directly over TLS/WebSockets; the landing page is separately served static
content. The server process owns the embedded assets, ephemeral rooms, file streams, and the
statistics endpoint. When configured, aggregate statistics history is atomically
checkpointed to an operator-owned state path. TLS private keys, persistent
state, release credentials, and deployment configuration are operator-owned
inputs, not source or image assets.

The main threat assumptions are hostile browser input, untrusted file names and
sizes, malicious clients retaining connections, compromised package/action/image
inputs, and accidental publication from CI. Existing CORS and server-boundary
tests cover request/client limits. Operators must provide TLS files read-only,
limit network exposure to the intended WebSocket port, and protect release
environment approval.

## Fresh-checkout quality commands

These commands require CMake 3.20+, Ninja, GCC, Node 22, ccache (optional),
shellcheck, and cppcheck. They do not publish anything.

```sh
cmake --preset core-coverage-gcc
cmake --build --preset core-coverage-gcc
ctest --preset core-coverage-gcc
npm run check:web
npm run coverage:browser
./scripts/run-static-analysis.sh
./scripts/check-release-inputs.sh
./scripts/check-release-contract.sh
./scripts/container-smoke.sh --verify-only
./scripts/release-dry-run.sh
```

The CMake configure output must report ccache when it is installed. The source
checksum, SPDX SBOM, and provenance generated by the input check are ignored
under `dist/metadata/`; CI uploads them for 14 days. The dry run must say that
no registry, tag, release, or remote destination changed.

Full native and container checks use the committed oatpp 1.4 sources. Build the
verified local prefix containing oatpp, oatpp-websocket, and oatpp-openssl with:

```sh
./scripts/build-vendored-oatpp.sh
CONSPIRE_DEPS_PREFIX="$PWD/build/deps" ./scripts/build-container.sh
```

Public oatpp 1.3.x is incompatible and deliberately never substituted.

## Release policy

The `quality`, `supply-chain`, `container-smoke`, and `release-dry-run` jobs
are required predecessors of publication. The normal workflow has read-only
contents permission. Publication can only be manually dispatched through the
protected `release` environment and must use narrowly scoped credentials.

All actions use full commit IDs and the runtime base uses an image digest.
Trivy blocks HIGH and CRITICAL findings. A temporary exception is allowed only
in the protected release record with a tracking issue, accountable owner,
rationale, and expiry no later than 30 days; an expired exception blocks the
release. Review dependency and image advisories weekly and immediately when an
advisory affects a pinned input.

## Troubleshooting and contribution checklist

- Missing oatpp prefix: run `make deps` or
  `./scripts/build-vendored-oatpp.sh`; do not install or fetch oatpp 1.3 as a
  workaround.
- Docker daemon unavailable: run `container-smoke.sh --verify-only` for the
  Dockerfile contract and record that a daemon was unavailable for image smoke.
- Certificate errors: mount `privkey.pem` and `fullchain.pem` at `/run/certs`
  read-only; see the deployment guide for systemd paths.
- Invalid statistics state: Conspire starts with empty in-memory statistics and
  leaves the invalid file untouched. Move or repair it before restarting to
  re-enable persistence at that path.
- Before opening a PR: run every fresh-checkout command above, keep generated
  `dist/` and local certificates untracked, and update tests/documentation for
  observable behavior changes.

Deferred risk owner: release maintainers. Review date: 2026-09-30. The bounded
risk is the unavailable compatible oatpp 1.4 prefix; it prevents full native,
image, and scanner evidence but does not authorize an incompatible dependency
substitution.
